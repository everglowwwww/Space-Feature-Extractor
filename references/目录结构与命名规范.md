# 共享办公空间特征提取 · 目录结构与命名规范 v1.0（已冻结）

> 适用仓库：`Space-Feature-Extractor`（本 skill）
> 冻结日期：本规范经讨论确认后即成最终执行依据；对 `input/` 与 `output/` 的整理均以本文件为准。
> 单元命名约定：项目文件夹基名统一用**无空格**中文（与项目夹 `1-北京盈科中心` 基名一致），单元夹 = `{项目基名}-{NN}`。原数据中个别单元名带空格（如 `北京 盈科中心-1`）在整理时统一去空格。

---

## 0. 总原则

- **层级语义**：项目(building) > 空间单元(unit)。
- **input / output 严格镜像**：`output/` 下与 `input/` 保持完全相同的项目/单元层级，便于双向定位。
- **路径保留中文**（定稿选择）：目录名用中文，可读性强。
- **单元序号为局部索引**（定稿选择）：序号是项目内的局部编号，非全局唯一码。
- **路径名即显示名**：中文名直接体现在路径上，不加 ASCII code 映射。
- **命名无空格**：项目、单元名统一不含空格，规避 shell/脚本的空格与引号问题。

## 2. 项目目录命名（定稿）

格式：`{序号}-{项目中文名}`

- 序号沿用现有 1~18，与总平面文件编号（`北京-5`、`北京-8`…）逻辑对应。
- 现有：`1-北京盈科中心` … `7-北京朝阳大悦城`
- 新增占位（尚未拆分，先建空文件夹）：`8-北京王府国际中心`、`9-北京中航产融大厦`、`10-北京好世界商业广场`、`11-北京隆福寺街95号`、`12-北京远洋光华国际大厦`、`13-北京辉煌时代大厦`、`14-北京世茂大厦`、`15-北京宫霄大厦`、`16-北京酒仙桥路6号`、`17-北京东煌大厦`、`18-北京酒仙桥14号`。

## 3. 单元目录命名（定稿选择：候选1，无空格）

格式：`{项目中文名}-{NN}`，`NN` 为两位补零的局部序号，**项目中文名不含空格**。

- 例：`北京盈科中心-01`、`北京国航世纪-03`、`北京三里屯11号-04`。
- `NN` 补零保证按字典序/自然序排序稳定（`01`<`02`<…<`09`）。

### 单元层 old → new 映射（执行时按此改名）

| 旧路径（原样，可能带空格） | 新路径（统一无空格） |
|--------|--------|
| `1-北京盈科中心\北京 盈科中心-1` … `-9` | `北京盈科中心-01` … `-09` |
| `2-北京国航世纪\1` `\2` `\3` | `北京国航世纪-01` `-02` `-03` |
| `3-北京望京国际中心\1` … `\5` | `北京望京国际中心-01` … `-05` |
| `4-北京慈云寺\1` … `\4` | `北京慈云寺-01` … `-04` |
| `5-北京互联网金融中心\1` … `\5` | `北京互联网金融中心-01` … `-05` |
| `6-北京三里屯11号\1` … `\4` | `北京三里屯11号-01` … `-04` |

## 4. 单元内文件命名（定稿选择：方案甲，标准化）

每个单元内部统一为以下标准文件名：

| 约定文件名 | 说明 | 现原始名（需映射） |
|------------|------|--------------------|
| `plan.png` | 平面图 | 盈科系：`AI 北京盈科中心-*.png`；其他：`平面-*.png` |
| `photo_01.jpg` | 人视图1 | `人视图-1.jpg` / `人视角-1.jpg` |
| `photo_02.jpg` | 人视图2 | `人视图-2.jpg` / `人视角-2.jpg` |
| `photo_0N.jpg` | 第 N 张人视图（若有） | `人视图-N.jpg` |
| `unit.dxf` | CAD 图纸（DXF） | `DXF *.dxf` / `DXF-*.dxf` |

> **本文件夹（input 侧）只放人工素材**。`llm_understanding.json` 是阶段A的产物，归 `output/` 侧（见 §5）。

**生成顺序**：`plan.png / photo_*.jpg / unit.dxf` 由整理脚本重命名/复制而来（人工把关）；`llm_understanding.json` 由阶段A（DeepSeek 视觉 + DXF 几何融合）写入 `output/`。

## 5. output 镜像规则（定稿）

**路径镜像**：`output/` 与 `input/` 的 `{项目}/{单元}` 路径**逐一对应、名称一致**。

- 项目夹：`output/1-北京盈科中心/` … `output/7-北京朝阳大悦城/`，以及占位项目 `8-北京王府国际中心/` … `18-北京酒仙桥14号/`（与 input 同步镜像建空夹；**output 空骨架在整理时一次性建全**）。
- 单元夹：`output/{项目}/{项目中文名}-{NN}/`（如 `output/1-北京盈科中心/北京盈科中心-01/`）。

**单元内文件（全部为生成内容）：**

| 文件 | 来源 |
|------|------|
| `llm_understanding.json` | 阶段A：DeepSeek 视觉 + DXF 几何融合产物 |
| `features.json` | 阶段B，英文 key（程序读取，case_name + 56 特征） |
| `features_cn.json` | 阶段B，中文 key + 单位（人类阅读） |
| `features.csv` | 阶段B，表格版 |
| `plan_binary.png` | 阶段B，平面二值化 |
| `seg_semantic_0N.png` | 阶段B，语义分割纯色图（N=1..照片数） |
| `seg_overlay_0N.png` | 阶段B，语义分割叠加图（带图例，N=1..照片数） |
| `report.html` | 阶段B（可选，`--report`） |

**批量模式**：`output/` 根下另生成 `batch_summary.json` / `batch_summary.csv`（每案例状态/耗时/特征数）。

**废弃示例归档**：`output/北京 盈科中心-5/`（旧版平铺示例产出）与 `input\北京 盈科中心-5` 一并视为弃用。整理时将它们移到 skill 根 `_legacy/` 目录归档（保留但不参与新分析）。

## 6. manifest（清单，用于状态追踪）

- 位置：skill 根目录 `manifest.csv`，由 `scripts/gen_manifest.py` 自动生成。
- 字段：`项目 / 项目编号 / 项目中文名 / 旧单元目录 / 单元(新名) / 新单元路径 / 平面图源 / 照片源 / DXF源 / AI源文件 / 状态(待分析 / 阶段A完成 / 阶段B完成)`。
- 另生成 `input_rename_map.csv`（每 input 侧源文件 → 标准目标名），供执行脚本直接读取。
- 注：`llm_understanding.json` 属 output 侧产物（阶段A），不进入 input 侧改名表。

## 7. 明确不动 / 忽略

- `input\北京 盈科中心-5` 与 `output\北京 盈科中心-5`：均为旧版平铺示例，视为弃用，整理时一并**归档到 skill 根 `_legacy/`**（保留但不参与新分析）。
